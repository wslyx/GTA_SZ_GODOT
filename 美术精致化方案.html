深城纪 Godot 版 · 美术精致化方案

2026-10-21 · 基于 10 张 1920×1124 实机截图（Godot 4.7.1 / Vulkan / RTX 4060，画质档默认 medium）· 截图存于 tools/shots/d1~d10_*.png · 本轮只做诊断，未改任何代码
结论先行：整体框架已经相当完整（光照三档、立面多样性、窗光、烘焙 AO、SSR 都在工作）， 目前拉低精致感的短板按影响面排序是—— ① 水面平涂（白天最伤画面）→ ② 日落档全画面红罩染 → ③ 雨丝观感假 → ④ 夜街路面照度不足 → ⑤ 草地/路面微观细节缺失。 其中 ①③⑤ 恰好对应未完成清单里的既定工单（B1 平面镜、地面材质缺口），②③ 属于本轮新发现。

一、逐张诊断

1.1 白天街景（d1）—— 基本盘良好，细节欠打磨

滨海大道 · 白天 · 画质中
  • 天空干净但偏「空」：几乎没有可见云形，地平线过渡略生硬。
  • 路面近景是一整块均匀灰：沥青颗粒/磨旧痕迹在低速视角下完全读不出来，车道线崭新等宽。
  • 行道树冠层稀疏，「秃枝感」明显（d1/d6/d7 多张可见），与热带城市植被预期不符。

1.2 日落街景（d2）—— 本轮新发现的最大观感问题

滨海大道 · 日落 · 画质中
  • 全画面被玫瑰红罩染：树冠被染成艳红（几乎像秋枫），左侧楼群呈暗枣红，路面偏粉。
  • 天空却是一大片灰紫云，没有金色地平线与日落辉光——「地上红、天上灰」互相打架，观感是「脏」而不是「暖」。
  • 佐证：d7（日落俯瞰）同样的红染 + 水面只有一道孤立的亮斑光柱。
  • 注意：日落 HDR 与曝光是之前逐项标定过的（修复记录第二十五节），动它之前必须先拿原版同机位截图比对，确认红染来自「太阳颜色 × 树冠反照率」还是本来如此。

1.3 夜景街景（d3）—— 氛围成立，路面欠光

滨海大道 · 夜晚 · 画质中
  • 星空 + 城市辉光云 + 立面窗光都成立，天空是三档里最好的。
  • 但本段路面几乎纯黑，车道线「浮」在黑底上；路灯灯池在这段路上一个都没有（右侧人行道仅一 faint 池）。
  • 公共照明 clipmap 已实现（修复记录第二十节），问题更可能是本路段灯位稀疏 / 灯池半径小，需与原版对照确认。

1.4 雨天（d4 低档 / d5 高档）—— 湿路成立，雨丝穿帮

雨天 · 日落 · 画质低
雨天 · 日落 · 画质高
  • 湿路反射（中央亮斑）成立，低/高档在静帧下差异不大——低档兜底 SSR 有效。
  • 雨丝是均匀的白色短竖条：等长、等亮、间距均匀，像渲染故障而不是雨。这是三档天气里最假的元素。
  • 路面缺少水洼「斑块」感：整条路均匀变暗 + 一条镜面亮带，原版 puddles 应有碎块状积水。

1.5 白天俯瞰（d6）与白天飞行（d9）—— 水面是最大短板

无人机视角 · 白天 · 画质中
飞行视角 · 白天 · 画质中
  • 海面是纯色平涂：饱和青绿色、零反射、零波纹、零岸边过渡，占画面近一半时「塑料感」最强。这正是未完成清单 B1 立案的结构性缺口（原版用 512 平面镜，本版只有 IBL + SSR）。
  • 草地是大面积均匀荧光绿，从空中看完全平（未完成清单 B6 有立案：地面材质现只用一张宏观贴图）。
  • 道路网、立交匝道、远景天际线的结构本身是好的。

1.6 夜间俯瞰（d8）—— 全场最佳，说明方向是对的

无人机视角 · 夜晚 · 画质中
  • 灯池沿路网铺开、天际线窗光分层、水面深色收敛——这张已经「像回事」。
  • 小瑕疵：路面灯池偏黄绿色调（路灯色温可以再核一遍原版）；远处岸线有一圈发白的「灯带糊」。

1.7 夜间飞行（d10）—— 好看，但有一条穿帮接缝

飞行视角 · 夜晚 · 画质中
  • 银河、城市灯海、航舰灯光都成立。
  • 画面中部有一条横贯的暗色矩形带（左侧尤其明显）——疑似远景城市壳分块边缘或雾过渡断层，属于疑似渲染缺陷而非风格问题，建议优先定位。

二、精致化方案（供拍板）

分两条线：按原版补齐 = 不偏离一比一口径的既定工单； 超越原版 = 会偏离一比一口径，需你明确授权； 缺陷修复 = 不改风格只修穿帮。

#项目类型解决什么预估风险
P1 平面镜水面（清单 B1）
SubViewport 镜像相机一次服务水面 + 湿路		 按原版补齐 白天海面平涂（d6/d9）、水面倒影不清、雨天镜面感弱——单点观感提升最大 2–3 天 中高（多一个 render target，需评估低档降级）
P2 雨丝与水洼观感重做 超越原版缺陷修复 d4/d5 的「白色短竖条」假雨丝；按原版 puddles 数据做斑块状积水（雨丝重做属超越项，水洼斑块属补齐） 1–2 天 低
P3 日落档红罩染校准 缺陷修复 d2/d7 的「地上红、天上灰」打架。前置条件：先取原版同机位截图（顺带解锁清单 C1「白天建筑偏亮」的比对），确认后再决定改太阳色/树冠反照率还是不动 比对 0.5 天 + 视结论 1 天 中（动已标定参数，需像素量化护栏）
P4 夜街灯池密度 / 色温核查 按原版补齐 d3 本路段零灯池、d8 灯池偏黄绿。先对照原版布灯数据，判断是漏布还是口径差异 0.5–1 天 低
P5 夜间飞行横向暗带定位（d10） 缺陷修复 远景壳分块边缘 / 雾断层穿帮。先复现定位（用 hide 键二分 distant/facades），再修 0.5–1 天 低
P6 地面微观材质：路面近景颗粒 + 草地分层（清单 B6/A5 关联） 按原版补齐 d1 路面平、d6 草地荧光绿平涂。含 A5 中湾铺装、ground-relief 完整材质 2–3 天 中
P7 腾讯滨海大厦逐窗格亮灯（清单 A4） 按原版补齐 夜景地标辨识度：幕墙从整片亮改为随机窗格点亮 1–2 天 中高（几何处理）
P8 行道树冠层加密 超越原版 d1/d6 的「秃枝感」。换/加 foliage 卡或调冠层密度——原版树资产同源，属在原版基础上的替换 1–2 天 中（资产替换需挑选）
P9 座舱内饰（清单 B3）：仪表盘 / 方向盘几何 按原版补齐 第一人称车内代入感（截图覆盖不到，但对玩家感知明显） 1–2 天 低

建议批次

批次内容理由
第 1 批P5 暗带定位 + P4 灯池核查 + P3 原版截图比对（三个排查型小项并行）先定性再动手，半天到一天能出全部结论
第 2 批P1 平面镜水面观感提升最大的一项
第 3 批P2 雨丝水洼 + P3 按比对结论实施天气族一次做齐
第 4 批P6 地面材质 + P7 大厦亮灯两处独立着色器，互不影响
第 5 批P8 树冠 + P9 座舱（可选）超越项与体验项，看前三批效果再定

三、执行约定（沿用项目既有铁律）

  • 凡改画面，必跑 tools/_shot.tscn 开窗截图 + compare_shots.py/像素统计做前后量化对比；无头跑通不等于画面对。
  • 「白天建筑偏亮」已标定完毕，不得借本轮顺手改曝光 / albedo——会把已对齐的日落与夜景一起带偏（清单 C1）。
  • 新着色器 / 新脚本沿用已知坑清单：新 class 必须 preload、var x := 遇 Variant 会推断失败、GDScript 负数取模用 fposmod。
  • 本轮环境备注：截图必须用 .NET 版 Godot（Godot_v4.7.2-stable_mono_win64_console.exe）——普通 4.7.1 版加载不了 C# 步行角色程序集，会直接退出（本轮实测踩到）。
